# Choosing Layout

## Overview

A still's shape: the foundation every still keeps, the catalog of single-image and carousel structures, how to suggest three from the study, and how to dress them as concept cards. The words follow [writing-copy.md](./writing-copy.md); the look follows [directing-still.md](./directing-still.md).

## Guidelines

### The foundation

Every still keeps these.

| # | Rule | How |
| --- | --- | --- |
| 1 | One focal point | The eye lands on one thing first: the headline, the screen's result, the number or the old-way artifact. Everything else is quieter in size, weight or colour |
| 2 | Read at a glance | The focal point and the headline read in ~1 s at feed size; the whole frame in ≤ 3 s, within [writing-copy.md](./writing-copy.md) → **Word budgets** |
| 3 | For me, at first sight | The headline or the picture names the trade or role, or shows its old-way artifact ([writing-script.md](./writing-script.md) → **The viewer**) |
| 4 | One message | One audience, one task, one core line ([writing-script.md](./writing-script.md) → **Core line, anchor phrase, value frame**) |
| 5 | The picture proves | The app's own screen, its result or the old-way artifact carries the claim; decoration never stands in for proof |
| 6 | Brand in every frame | The mark in one quiet corner of every frame, never over the focal point ([directing-still.md](./directing-still.md) → **Brand on a still**) |
| 7 | The ask after the context | The offer and the CTA sit in the O zone or a carousel's last frame; only Offer card leads with the offer |
| 8 | The image says little | The terms, the link and the detail go in the post text, written when it is posted |
| 9 | True and proven | [promotion-contract.md](./promotion-contract.md) → **Honesty rules** |

### Single-image structures

Zones are in read order. Marks: **P** carries the promise; **B** names the brand, with the sold line when sold ≠ shown; **O** carries the offer and the CTA.

| Structure | Family | Zones, in read order | Focal point | From the source alone | Fits |
| --- | --- | --- | --- | --- | --- |
| Hero screen | Show-led | Headline P · the key screen, large, its result in view B · O | The screen's result | Yes | A category the audience knows by name; one screen shows the win |
| Before / After | Problem-led | One headline P · the old-way artifact beside the app's screen, the same task in both B · O | The seam between them | Yes, when the old way has a showable artifact | Ready to switch |
| Pain call-out | Problem-led | The pain in the audience's words, large P · the artifact behind or beside it · the answer line B · O | The pain line | Yes | Problem-aware, cold |
| Result shown | Show-led | The finished result as the screen states it P · what made it B · O | The result | Yes | Unaware; the result reads in one frame |
| Feature trio | Show-led | Headline P+B · 3 tasks, each input → result with a crop of its screen · O | The headline, then the crops | Yes | 3 features of one flow |
| Anatomy | Show-led | Headline P · one screen with 3–5 callouts to its parts B · O | The screen | Yes | One dense screen does the job |
| Statement | Brand-led | One line of type P+B · the mark · O, small | The line | Yes | A seller, not one app; brand awareness |
| Range | Brand-led | Headline P+B · 3–6 labelled tiles of what the seller makes, the pain in the headline or in each tile's old-way artifact · O | The headline, then the tiles | Yes, from the seller's shipped work or sample apps, each disclosed | A seller who builds many kinds of thing |
| Offer card | Moment-led | The offer P+B+O · what it covers · how to claim | The offer | Yes | Warm audiences who already engaged; never cold |

### Carousel structures

2–10 frames of one ratio. Feeds often show frame 1 alone, so it stands as a single without the ask: the promise and the brand. The last frame is the ask.

| Structure | Family | Frames, in order | Count | Fits |
| --- | --- | --- | --- | --- |
| Problem → Solution | Problem-led | Pain P · what it costs them · reveal B · 1–2 proofs · ask O | 5–6 | Problem-aware, cold |
| Listicle | Show-led | Count hook P+B · one item a frame · ask O | 4–8 | Several needs or features of one kind |
| How it works | Show-led | Promise P · one step a frame B · result · ask O | 4–7 | A process the viewer must trust before acting |
| Before / After per task | Show-led | Contrast hook P · one split a frame B · verdict + ask O | 4–6 | Several old-way tasks the app replaces |
| Range tour | Brand-led | Statement P+B · one kind of work a frame · ask O | 4–7 | A seller who builds many kinds of thing |

- Each frame holds one idea and reads on its own; the frames share one grid, one type system and one mark position.
- Frame 1 carries a swipe cue: an element running off its right edge into frame 2, or a frame counter ("1/5"); never an arrow sticker alone.
- A line or band may run across a frame edge; a word never does.

### Choosing

Suggest; the user decides. What is sold never picks the structure.

1. **Read the inputs** from `product.md`: awareness, whether the category has a common name, the old way's artifact, the features to show and their count, the proof, and what is sold.
2. **Pick 3 structures per format asked**, from at least 2 families, each one the source alone can carry:

   | Input | Leans to |
   | --- | --- |
   | Problem-aware, a showable artifact | Pain call-out, Before / After, Problem → Solution |
   | Unaware; the result reads in one frame | Result shown, Hero screen |
   | 3 or more features of one flow | Feature trio, Anatomy, Listicle |
   | A process the viewer must trust | How it works |
   | The seller, not one app | Statement, Range, Range tour |
   | Warm, retargeted | Offer card |

3. **Both formats asked** → 3 cards each; a pick may pair a single with a carousel on one concept, the single then being frame 1 made whole with its ask.

### Concept cards

1. One card per suggested structure, each with its message angle ([choosing-style.md](./choosing-style.md) → **Concept cards**, the angle table) and the still preset that fits ([directing-still.md](./directing-still.md) → **Presets**). Two cards on one structure differ in message, never only in look.
2. Each card names the audience, the format (single, or carousel and its frame count), the ratio, the structure, the angle, frame 1's headline, the focal point, the preset, a one-line reason and the main risk.
3. The user picks a card, mixes across cards, or names their own; the pick goes in **Spec**.

Three single-image cards for a bakery order app whose orders arrive by chat and land in a paper notebook, for cold owners, 4:5:

| Field | Card 1 | Card 2 | Card 3 |
| --- | --- | --- | --- |
| Audience | Bakery owners, orders by chat | Same | Same |
| Format · ratio | Single · 4:5, with a 9:16 cut | Single · 4:5, with a 9:16 cut | Single · 4:5, with a 9:16 cut |
| Structure | Pain call-out | Result shown | Before / After |
| Angle | Relief | Outcome | Relief |
| Headline | "Cake orders lost in the chat again?" | "Tomorrow's bake list, from today's orders." | "The notebook, or one board." |
| Focal point | The chat thread, cropped inside a drawn phone | The bake list screen | The seam between the notebook and the board |
| Preset | Paper Desk | Product Hero | Split |
| Why it fits | Orders arrive by chat today | The result reads in one screen | The old way is a paper notebook |
| Main risk | The chat may read as the product | No pain shown; relies on the result reading fast | Two pictures halve the size of each |
